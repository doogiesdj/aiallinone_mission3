# Mini NPU Simulator

NumPy·pandas 같은 외부 라이브러리 없이 파이썬 표준 라이브러리 `json`, `time`만으로 **MAC(Multiply-Accumulate) 연산을 이중 반복문으로 직접 구현**한 패턴 판별 시뮬레이터입니다. 입력 패턴이 **Cross(+)** 인지 **X** 인지를 두 필터와의 MAC 점수로 판별합니다.

---

## 1. 프로젝트 개요

NPU의 핵심 연산 단위인 `Accumulator ← Accumulator + (A × B)`(`out += a * b`)를 코드 수준에서 재현합니다.

- **동적 N×N 처리**: 행렬 크기를 하드코딩하지 않고 `3×3`, `5×5`, `13×13`, `25×25`를 같은 로직으로 처리
- **Epsilon 동점 판정**: IEEE 754 부동소수점 오차를 고려해 점수 차이가 `EPSILON = 1e-9` 미만이면 `UNDECIDED`
- **3갈래 실패 진단**: 데이터/스키마 오류, 로직 오류, 수치 비교 오류를 사용자 정의 예외로 분리
- **성능 측정**: I/O를 제외한 순수 MAC 연산 시간만 측정해 $O(N^2)$ 복잡도 확인

## 2. 시작하기

### 요구 사항
- **Python 3.10 이상** (`int | None` 타입 표기 사용)
- 외부 패키지 설치 불필요 — 표준 라이브러리 `json`, `time`만 사용

### 실행
`main.py`와 `data.json`을 같은 폴더에 두고 실행합니다.

```bash
python main.py
```

Windows 콘솔에서 한글이 깨지면 UTF-8 출력을 지정합니다.

```bash
set PYTHONIOENCODING=utf-8      # cmd
$env:PYTHONIOENCODING="utf-8"   # PowerShell
```

## 3. 사용 예시

### 모드 1 — 사용자 입력

각 행을 공백(또는 쉼표)으로 구분해 입력합니다. 숫자 개수가 맞지 않거나 숫자가 아니면 안내 후 해당 행을 다시 입력받습니다.

```text
[필터 A] 3×3 행렬을 입력하세요
  1행 입력 > 0 1
  입력 형식 오류: 각 줄에 3개의 숫자를 공백으로 구분해 입력하세요. (입력된 숫자 2개) 1행을 다시 입력해 주세요.
  1행 입력 > 0 1 0
...
--- 필터 저장 확인 ---
  [저장 완료] 필터 A:
    0 1 0
    1 1 1
    0 1 0
  [저장 완료] 필터 B:
    1 0 1
    0 1 0
    1 0 1
...
--- 판별 결과 ---
필터 A MAC 점수 : 5
필터 B MAC 점수 : 1
점수 차이 (|Δ|) : 4 (기준 epsilon = 1e-09)
연산 시간       : 0.005500 ms (MAC 2회)
판정 결과       : A
```

이어서 3×3 성능 분석 표가 출력됩니다. 두 점수 차이가 epsilon 미만이면 판정 결과는 `판정 불가`입니다.

## 4. `data.json` 형식

### 미션 공식 형식

```json
{
  "filters": {
    "size_5":  {"cross": [[...]], "x": [[...]]},
    "size_13": {"cross": [[...]], "x": [[...]]},
    "size_25": {"cross": [[...]], "x": [[...]]}
  },
  "patterns": {
    "size_5_1":  {"input": [[...]], "expected": "+"},
    "size_13_1": {"input": [[...]], "expected": "x"}
  }
}
```

- `patterns`의 키 `size_{N}_{idx}`에서 **N을 추출해 `size_N` 필터를 선택**합니다. 키는 케이스 이름으로도 쓰입니다.
- 선택한 필터와 패턴 크기가 다르거나(`size_5_4`에 13×13 입력 등) `size_N` 필터가 없으면 그 케이스만 `FAIL`(데이터/스키마 오류)로 처리합니다.
- 이 형식의 예시가 **`data_official_format.json`**입니다. 메뉴 2번에서 경로에 `data_official_format.json`을 입력하면 실행됩니다.

### 그 밖에 지원하는 형식

루트가 케이스 리스트이거나 `{"filters": ..., "cases": [...]}` 형태여도 읽습니다. 동봉한 `data.json`은 이 형식으로, 3×3 케이스와 오류 진단용 케이스를 함께 담고 있습니다. 키 이름은 아래처럼 여러 별칭을 허용합니다.

| 항목 | 허용 키 | 비고 |
| :--- | :--- | :--- |
| 케이스 목록 | `patterns`(객체), `cases`, `test_cases`, `tests`, `data` | 루트가 객체일 때 |
| 케이스 이름 | `id`, `name` | 없으면 `Case-번호` |
| 입력 패턴 | `input`, `pattern`, `matrix`, `data` | N×N 숫자 행렬 |
| 기대 정답 | `expected`, `label`, `answer`, `target` | |
| 필터 | 케이스의 `filters`/`filter`, 또는 `filter_cross` + `filter_x`, 없으면 루트 `filters` | 루트 `filters`는 `size_5` 또는 `"5"` 키의 크기별 매핑 지원 |
| 기대 점수 (선택) | `expected_scores` | `{"cross": 9, "x": 1}` 형태, epsilon 기준 비교 |

**라벨 정규화**: `'+'`, `'cross'` → `Cross`, `'x'` → `X`, `'undecided'` → `UNDECIDED` (대소문자·앞뒤 공백 무관)

## 5. 구현 원칙

1. **MAC 직접 구현 (`compute_mac`)**: 누적 변수를 `acc = 0.0`으로 초기화한 뒤 이중 `for`문으로 `acc += row_a[j] * row_b[j]`를 수행합니다.
2. **입력 검증 (`parse_finite_float`, `validate_square_matrix`)**: 정사각 행렬 여부와 숫자 변환을 검사하며, `bool`, `NaN`, `Inf`는 거부합니다.
3. **Epsilon 비교 (`classify_pattern`)**: `abs(score_cross - score_x) < 1e-9`이면 `UNDECIDED`, 아니면 점수가 큰 쪽으로 판별합니다.
4. **실패 원인 분리**: 예외 계층 `SimulatorError` 아래 세 가지로 구분합니다.

   | 예외 | 분류 | 발생 조건 |
   | :--- | :--- | :--- |
   | `DataSchemaError` | 데이터/스키마 오류 | 파일·키 누락, 크기 불일치, 숫자 파싱 실패 |
   | `LogicError` | 로직 오류 | 판별 라벨이 기대 라벨과 다름 |
   | `NumericalComparisonError` | 수치 비교 오류 | `UNDECIDED` 경계 불일치, 기대 점수 오차 초과 |

5. **안전한 파일 처리 (`load_json_file`)**: `try-except-else-finally`로 예외와 무관하게 파일을 닫습니다.
6. **전각 문자 정렬 (`display_width`, `pad_display`)**: 한글·한자 등은 콘솔에서 2칸을 차지하므로, 유니코드 범위로 표시 폭을 계산해 케이스 이름에 한글이 섞여도 결과 표의 열을 맞춥니다. 표준 라이브러리 제약상 `unicodedata` 대신 범위 상수(`WIDE_CHAR_RANGES`)를 직접 사용합니다.

| `case_09_err_schema` | 입력 `2×2` vs 필터 `5×5` 크기 불일치 | FAIL (데이터/스키마) |

| :--- | :--- | :---: |

| `size_5_3` | Cross 칸 `0.1 + 0.2` vs X 칸 `0.3` 부동소수점 동점 → `UNDECIDED` | PASS |
| `size_5_4` | 키는 5인데 입력이 13×13 → `size_5` 필터와 크기 불일치 | FAIL (데이터/스키마) |
| `size_5_5` | Cross 패턴에 기대값 `x` 지정 | FAIL (로직) |
| `size_5_6` | `size_5_3`과 같은 동점 입력에 기대값 `+` 지정 | FAIL (수치 비교) |

### 6.2 실패 원인 분석

실패는 원인에 따라 세 갈래로 나누어 진단하며, 각각 별도 예외 클래스로 구분해 콘솔에 분류와 함께 출력합니다.

1. **데이터/스키마 문제 (`case_09_err_schema`, `size_5_4`)**: 입력 패턴은 2×2인데 비교할 필터는 5×5입니다. MAC 연산은 같은 위치의 값끼리 곱하므로 크기가 다르면 계산 자체가 성립하지 않습니다. 공식 형식에서는 키 `size_{N}_{idx}`의 N으로 필터를 고르기 때문에, 키의 N과 실제 패턴 크기가 다른 경우도 같은 방식으로 잡아냅니다. 연산 전에 크기를 검증해 이 케이스만 FAIL로 처리하고 다음 케이스로 넘어가므로 프로그램은 멈추지 않습니다.
2. **로직 문제 (`case_10_err_logic`, `size_5_5`)**: Cross 모양 패턴은 Cross 필터 9점, X 필터 1점으로 Cross로 판정되지만 기대값이 `x`로 적혀 있습니다. 판정 로직이 틀린 것이 아니라 정답 데이터가 틀린 경우이며, 실제 개발에서는 판정 함수와 정답 라벨 중 어느 쪽이 맞는지 점수를 근거로 확인해야 합니다.
3. **수치 비교 문제 (`case_11_err_epsilon`, `size_5_6`)**: 두 점수의 차이가 5e-10(`size_5_6`은 약 5.6e-17)으로 허용오차 1e-9보다 작아 동점(`UNDECIDED`)이 됩니다. 기대값은 `Cross`이므로 FAIL입니다. `==`로 비교했다면 이 차이 때문에 Cross로 판정되어 PASS가 되었겠지만, 이 정도 차이는 계산 오차와 구별할 수 없어 동점으로 보는 것이 이 프로그램의 비교 정책입니다.
4. **라벨 표기 차이로는 실패하지 않습니다**: 데이터에 `'+'`, `'cross'`, `'Cross'`, `'x'`, `'X'`가 섞여 있어도 `normalize_label()`이 표준 라벨 `Cross`/`X`로 통일한 뒤 비교하므로, 표기 차이 때문에 생기는 FAIL은 0건입니다.
5. **부동소수점 오차로도 실패하지 않습니다**: `case_08`, `size_5_3`처럼 `0.1 + 0.2`와 `0.3`은 컴퓨터 안에서 아주 조금 다르게 저장되지만, epsilon 비교 정책 덕분에 의도대로 `UNDECIDED`로 판정되어 PASS입니다.
6. 따라서 위 3건의 FAIL은 모두 오류 진단 기능을 확인하려고 일부러 넣은 케이스이며, 정상 케이스에서 발생한 FAIL은 없습니다.

### 6.3 시간 복잡도 분석 (O(N²))

**측정 기준**
- **포함**: `compute_mac()` 호출 구간만 `time.perf_counter()`로 측정
- **제외**: JSON 읽기, 행렬 생성, 콘솔 출력 등 입출력·준비 작업
- **방식**: 크기별 10회 반복 후 평균

**측정 결과 (Python 3.14.0, Windows 11)**

| 행렬 크기 | 연산 횟수 (N²) | 평균 시간 (ms) | 시간 배율 | 연산량 배율 |
| :--- | :---: | :---: | :---: | :---: |
| 3 × 3 | 9 | 0.001190 | 1.00x | 1.00x |
| 5 × 5 | 25 | 0.001910 | 1.61x | 2.78x |
| 13 × 13 | 169 | 0.008240 | 6.92x | 18.78x |
| 25 × 25 | 625 | 0.026770 | 22.50x | 69.44x |

> 측정값은 실행 환경과 시점에 따라 달라집니다.

**해석**
- `compute_mac`은 N×N 행렬의 모든 칸을 이중 반복문으로 정확히 한 번씩 방문하므로, 곱셈·덧셈 횟수가 N²에 비례하는 O(N²) 알고리즘입니다.
- 크기가 커질수록 시간이 늘어나는 추세는 연산 횟수 증가와 같은 방향입니다. 예를 들어 13×13에서 25×25로 갈 때 연산량은 약 3.70배, 시간은 약 3.25배 늘었습니다.
- 작은 크기에서는 시간 배율이 연산량 배율보다 낮습니다. 함수 호출, 크기 검증, 반복문 준비 같은 고정 비용이 연산 자체보다 큰 비중을 차지하기 때문입니다.
- 크기가 커질수록 고정 비용의 비중이 줄어 시간 배율이 연산량 배율에 가까워지며, 이는 O(N²) 추세를 뒷받침합니다.
- 실제 AI 모델은 수백×수백 크기의 필터를 수천 개 사용하므로 연산량이 매우 커집니다. 이런 단순 반복 곱셈·덧셈을 한꺼번에 병렬로 처리하기 위해 NPU 같은 전용 하드웨어가 필요합니다.
