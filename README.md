# Mini NPU Simulator

## 1. 프로젝트 소개
**Mini NPU Simulator**는 NumPy, pandas 등 외부 벡터화 라이브러리를 일절 사용하지 않고, 파이썬 표준 라이브러리(`json`, `time`)만을 이용해 **MAC(Multiply-Accumulate) 연산을 이중 반복문으로 직접 구현**한 패턴 판별 시뮬레이터입니다.

인공 뉴런($Y = \sum(W \times X) + B$)의 핵심 하드웨어 연산 단위인 `Accumulator ← Accumulator + (A × B)`(`out += a * b`)를 코드 수준에서 직접 구현하고, IEEE 754 부동소수점 정밀도 한계를 보완하기 위해 허용오차(`EPSILON = 1e-9`) 기반 동점(`UNDECIDED`) 판정 정책을 적용했습니다. 또한 `try-except-else-finally`와 사용자 정의 예외 계층을 통해 데이터/스키마 오류, 로직 오류, 수치 비교 오류를 분리 진단하며, 다양한 행렬 크기(`3×3`, `5×5`, `13×13`, `25×25`)의 순수 연산 시간을 측정해 $O(N^2)$ 복잡도를 실측 데이터로 검증했습니다.

- **실행 환경**: Python 3.12.5 (표준 라이브러리 `json`, `time`만 사용)
- **제출 구성**: `main.py`, `data.json`, `README.md`

### 요구 사항 및 제약

- **허용 라이브러리**: 파이썬 표준 라이브러리 `json`, `time`만 사용 (NumPy, pandas 등 외부 라이브러리 미사용)

### 실행 방법
`main.py`와 `data.json`을 같은 디렉토리에 둔 상태에서 아래 명령어를 실행합니다.

```bash
python main.py
```

실행 후 콘솔 메뉴에서 원하는 기능을 선택합니다.
- **1번 (모드 1 — 사용자 입력 모드)**: `3×3` Cross 필터, X 필터, 입력 패턴을 직접 입력해 판별 (행/열 개수 불일치 및 숫자 파싱 실패 시 재입력 유도)
- **2번 (모드 2 — `data.json` 일괄 판정 모드)**: `3×3`, `5×5`, `13×13`, `25×25` 테스트 케이스 일괄 평가 및 케이스 단위 `PASS`/`FAIL`·실패 사유 출력
- **3번 (성능 분석)**: 크기별(`3×3`, `5×5`, `13×13`, `25×25`) 순수 MAC 연산 10회 반복 평균 시간(ms) 및 연산 횟수($N^2$) 표 출력

## 3. 주요 기능 및 구현 원칙
1. **동적 $N \times N$ 행렬 구조**: 행렬 크기를 `3×3` 등으로 하드코딩하지 않고 `len()` 기반으로 동적 검증·연산하여 `3×3`, `5×5`, `13×13`, `25×25`를 동일 로직으로 처리합니다.
2. **모드 1 입력 검증 및 재입력**: 공백·쉼표 구분 입력을 파싱하며 열 개수 불일치, 빈 줄, 숫자 변환 실패(`ValueError`, `NaN`/`Inf`, `bool` 차단) 시 안내 메시지와 함께 재입력을 받습니다.
3. **라벨 정규화 함수 분리 (`normalize_label`)**: `expected`의 `'+'` 및 `filter`의 `'cross'`(대소문자·공백 무관)는 `'Cross'`로, `'x'`는 `'X'`로 통일해 문자열 비교 오류를 방지합니다.
4. **반복문 기반 MAC 직접 구현 (`compute_mac`)**: 누적 변수(`acc = 0.0`)를 초기화한 뒤 이중 `for`문으로 `acc += row_a[j] * row_b[j]` 연산을 수행합니다.
5. **Epsilon 기반 수치 비교 (`EPSILON = 1e-9`)**: 두 필터 점수 차이의 절댓값 `abs(score_cross - score_x)`가 `1e-9` 미만이면 동점인 `UNDECIDED`로 판정합니다.
6. **케이스 단위 방어적 예외 처리**: `load_json_file()`에서 `try-except-else-finally`로 파일 자원을 안전하게 정리하며, 평가 중 `DataSchemaError`, `LogicError`, `NumericalComparisonError`가 발생해도 프로그램이 종료되지 않고 해당 케이스만 `FAIL` 처리한 뒤 다음 케이스로 진행합니다.

## 4. 성능 분석 결과 ($O(N^2)$ 복잡도 검증)

### 측정 경계 (Measurement Boundary)
- **측정 포함 구간**: 순수 MAC 연산 함수 `compute_mac(pattern, filt)` 호출 구간만 `time.perf_counter()`로 측정
- **측정 제외 구간**: JSON 파일 읽기/파싱, 행렬 사전 생성(`build_synthetic_matrices`), 콘솔 출력(`print`) 등 **입출력(I/O) 및 준비 오버헤드 시간은 타이머 밖으로 완전히 분리**
- **측정 방식**: 각 행렬 크기별로 10회 반복 측정 후 산술 평균 시간(ms) 계산

### 크기별 연산 횟수 및 평균 수행 시간 (실측 결과)
| 행렬 크기 ($N \times N$) | 연산 횟수 ($N^2$) | 10회 반복 평균 시간 (ms) | 기준(`3×3`) 대비 시간 배율 | 기준(`3×3`) 대비 연산량 배율 |
| :--- | :---: | :---: | :---: | :---: |
| **3 × 3** | 9 | 0.003356 ms | 1.00x | 1.00x |
| **5 × 5** | 25 | 0.005693 ms | 1.70x | 2.78x |
| **13 × 13** | 169 | 0.021738 ms | 6.48x | 18.78x |
| **25 × 25** | 625 | 0.071733 ms | 21.38x | 69.44x |

### 복잡도 분석 요약
- `compute_mac`은 $N \times N$ 행렬의 각 좌표를 이중 반복문으로 순회하므로 이론적 연산 횟수가 $N^2$에 정확히 비례하는 $O(N^2)$ 알고리즘입니다.
- **소규모 구간(`3×3` → `5×5`)**: 연산 횟수는 2.78배 증가했지만 실행 시간은 1.70배 증가했습니다. 이는 연산량이 매우 작은 구간에서는 순수 곱셈·덧셈보다 함수 호출, 크기 검증, 파이썬 루프 진입 같은 **고정 오버헤드** 비중이 크기 때문입니다.
- **확장 구간(`13×13` → `25×25`)**: 행렬 크기가 커질수록 고정 오버헤드 비중이 희석되면서, 연산량 증가율($625 / 169 \approx 3.70$배)과 실측 시간 증가율($0.071733 / 0.021738 \approx 3.30$배)이 근접하게 수렴하여 $O(N^2)$ 추세가 뚜렷하게 나타납니다.

## 5. `data.json` 테스트 및 오류 진단 요약

제공된 테스트용 `data.json`은 `3×3`, `5×5`, `13×13`, `25×25` 정상 판별 및 라벨 정규화(`'+'`, `'cross'`, `'x'`), IEEE 754 부동소수점 오차(`0.1 + 0.2` vs `0.3`) 기반 `UNDECIDED` 판정 케이스와 3가지 실패 진단 케이스(데이터/스키마, 로직, 수치 비교)로 구성되어 있습니다.

- **총 케이스**: 11건 | **통과(PASS)**: 8건 | **실패(FAIL)**: 3건
- **통과(PASS) 8건**:
  - `case_01_3x3_cross` ~ `case_07_25x25_x`: `3×3`, `5×5`, `13×13`, `25×25` 크기 및 `'+'`/`'cross'`/`'x'` 정규화 정상 판별
  - `case_08_3x3_tie_fp`: `0.1 + 0.2`와 `0.3`의 미세 부동소수점 차이를 `EPSILON = 1e-9` 미만으로 판정하여 `UNDECIDED` 정상 통과
- **실패(FAIL) 원인 분류 3건 (진단 검증용)**:
  - **데이터/스키마 오류 (1건)**: `case_09_err_schema` — 입력 `2×2`와 필터 `5×5` 크기 불일치 감지 후 프로그램 중단 없이 `FAIL` 출력
  - **로직 오류 (1건)**: `case_10_err_logic` — `5×5` Cross 패턴의 기대 라벨을 `'x'`로 지정한 오분류 사례 검출 (`기대=X, 판별=Cross`)
  - **수치 비교 오류 (1건)**: `case_11_err_epsilon` — 두 필터 점수 차이가 `|Δ| = 5.000e-10 < 1e-9`인 동점 경계 사례 검출 (`기대=Cross, 판별=UNDECIDED`)

## 7. 구현 회고 및 트러블슈팅
- **라벨 정규화 분리로 비교 실패 방지**: 테스트 데이터의 `expected` 표기(`'+'`, `'cross'`, `'x'`)가 혼용되어도 `normalize_label()` 함수에서 `'Cross'`와 `'X'`로 일원화해 문자열 불일치로 인한 오판을 차단했습니다.
- **크기 불일치 시 프로그램 종료 방지**: `data.json` 일괄 판정에서 개별 케이스 검증 및 판정을 `try-except`로 격리하여, 잘못된 크기나 스키마 오류가 포함되어도 전체 배치가 멈추지 않고 실패 원인을 3갈래로 분류해 끝까지 리포트하도록 구성했습니다.
- **부동소수점 동점 경계 처리**: `0.1 + 0.2`처럼 이진 부동소수점 근사로 인해 완전히 같아지지 않는 값도 `EPSILON = 1e-9` 비교 정책으로 일관되게 `UNDECIDED`로 판정함을 검증했습니다.
